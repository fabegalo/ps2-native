# M1.1 — Despacho AOT de funções e saltos indiretos (2026-11-03)

## Entrega implementada

- Decodificador MIPS/R5900 limitado separado do fluxo de controle e do gerador: `mips.hpp/.cpp`, `control_flow.hpp/.cpp` e `aot.cpp`.
- Suporte novo a `JALR rd, rs`, inclusive `rs == rd` (destino capturado **antes** de sobrescrever o registrador de link). `JR` e `JALR` preservam delay slots; `JAL` e branches anteriores permanecem testados.
- Análise de ELF32 de `SHT_SYMTAB` / `SHT_DYNSYM` para identificar símbolos `STT_FUNC` válidos em segmentos executáveis `PT_LOAD`. Para ELF sem símbolos, `ps2n-aot ... --entry=0xADDRESS` aceita raízes de código verificadas do usuário.
- Descoberta por grafo de fluxo com alvos de saltos e chamadas diretas, continuações e delay slots. Nenhum dado arbitrário é interpretado como código apenas por parecer um endereço.
- Emissão AOT de **funções C++ nativas por bloco básico**, com despachante ordenado por endereços de entrada; não executa bytecode MIPS por interpretador.
- Despachante dinâmico aceita **somente entradas efetivamente recompiladas**. Destino não compilado lança erro com o PC, sem sucesso falso; não há fallback em M1.1.
- O código executável em RAM é verificado antes de executar uma tradução: quando uma instrução foi modificada, a execução é abortada (proteção conservadora contra código automodificável, não um JIT).
- Orçamento de instruções e contagem de instruções aposentadas preservados, incluindo execução dos delay slots.
- Cache incremental da fonte gerada preservado: `write_text_if_changed()` não altera o arquivo quando os bytes são idênticos. Nada copia o ELF ou o jogo inteiro.

## Prova executada localmente

- **GCC 14.2 Linux x86-64 / Release:** 6 de 6 testes CTest aprovados.
- **Clang 17 Linux x86-64 / Debug com ASan e UBSan:** 6 de 6 testes CTest aprovados.
- Fixture de autoria própria com ELF32 MIPS + **quatro símbolos STT_FUNC** (main, funções A/B/C) e uma versão sem símbolos.
- Fluxo end-to-end verificado: ELF → análise → C++ gerado → compilação host → chamadas indiretas → retorno. **28 instruções aposentadas**, `$v0=20`, `RAM[0x40]=12`, `RAM[0x44]=18`, `RAM[0x48]=20`.
- Testes negativos: destino `JALR` não identificado, ponteiro em RAM alterado para destino ausente, alteração de código carregado, instrução de controle em delay slot, tabela ELF simbólica inválida, opção de entrada fora de segmento, opcode desconhecido e orçamento insuficiente.
- Os três testes M0 anteriores continuam aprovados (37 instruções no smoke test principal).

## CI multiplataforma

- O workflow único `build.yml` inclui Windows x86-64/ARM64, Linux x86-64/ARM64, macOS Intel/Apple Silicon. Foi corrigido para usar o gerador `Visual Studio 18 2026` nos runners Windows VS2026 (o gerador VS2022 era a causa dos dois erros anteriores).
- **A aprovação dos runners remotos após esta alteração depende da execução do GitHub Actions**; não confundir resultados locais com validação dos seis targets.

## Limitações honestas

- Não é compatibilidade comercial de PS2: não há BIOS original, Browser, IOP, SPU2, VU, DMA, GS, GPU, controle, launcher, boot nem jogos jogáveis.
- AOT restrito ao subconjunto R5900 já coberto no M0 mais `JALR`. Sem MMI de 128 bits, FPU, precisão numérica PS2 completa, MMU, exceções, syscalls, cache coerente ou ciclo de hardware.
- Descoberta de funções ainda é conservadora: símbolos ELF verificados, raízes explícitas e caminhos diretos. Não há resolução automática universal de jump tables, overlays, código carregado em tempo de execução ou relocações.
- Endereços no meio de um bloco sem entrada de fluxo reconhecida podem não estar na tabela de despacho; adicionar entradas precisas, sem aceitar qualquer destino como válido. Entradas desconhecidas falham.
- Alterações no código executável são **detectadas e rejeitadas**, ainda não recompiladas. Não há fallback interpretado/JIT e nenhum comportamento é simulado como sucesso.
- O código emitido verifica integridade de memória de instrução por execução, com custo de desempenho. Otimização depende de suporte futuro a invalidação/coerência.
- Caminhos Unicode e longos ainda precisam ser testados em Windows real.

**Nenhum código GPL, BIOS, ISO, ROM ou jogo proprietário foi integrado.** M0 e M1.1 são protótipos técnicos, sem release para usuários finais.
